# AI 에이전트의 최초 연결 절차

## 1. 환경과 현재 상태

1. 현재 저장소 위치와 `AGENTS.md`, `SKILL.md`를 읽는다. 같은 저장소나 스킬이 이미 있으면 변경 사항을 보존하고 기존 소스를 갱신한다.
2. Windows와 Python 3.10 이상을 확인한다. `setup.ps1 -Check`는 사용 가능한 Python을 찾아 환경과 로컬 연결 상태를 출력한다. 필요한 경우 프로젝트의 기존 실행 방식부터 확인한다.
3. Python이 없으면 [공식 Windows 설치 안내](https://www.python.org/downloads/windows/)를 확인한다. `winget install --id Python.Python.3.12 --exact --scope user`처럼 사용자 범위에 설치하고 실제 실행을 확인한다. 설치 권한 또는 설치 화면 조작이 필요할 때 그 행동만 요청한다.
4. `doctor` 결과의 `next_step`부터 진행한다. 기존 앱과 토큰, 템플릿이 준비되어 있으면 재생성 과정을 건너뛴다.
5. WSL이라면 Windows Python과 Windows 파일 경로를 사용한다. Python의 OAuth 콜백 서버와 브라우저가 같은 PC에서 연결되는 실행 경로를 준비한다.

## 2. 브라우저 도구 연결

사용 가능한 도구와 플러그인을 먼저 확인한다. 도구 설명과 설치된 브라우저/computer-use 스킬을 읽고 실제 페이지에 접근할 수 있는지 확인한다. 화면을 볼 수 있다는 이유만으로 클릭/입력 도구가 연결됐다고 판단하지 않는다.

### Codex

- 앱의 오른쪽 브라우저에서 로그인과 입력이 가능하면 그 창에서 진행한다.
- 기존 로그인 세션이 필요하면 Chrome 연결을 사용한다. 이미 연결한 Chrome과 해당 탭부터 확인한다.
- 연결이 없으면 앱의 `Settings > Computer Use`에서 브라우저와 플러그인 선택, `Install extension` 화면을 준비한다. 설치 후 같은 화면의 `Manage`에서 연결 상태를 확인하고 브라우저를 @mention해 작업한다. 플러그인 검색 기능이 있으면 Browser 또는 Chrome 플러그인도 확인한다. [브라우저 공식 안내](https://learn.chatgpt.com/docs/browser?surface=app)와 [Chrome 확장 프로그램 공식 안내](https://learn.chatgpt.com/docs/chrome-extension)를 현재 환경과 대조한다.
- 확장 프로그램 설치와 연결, 필요한 사이트 권한 허용을 사용자에게 요청한다. 설치 후 실제 탭 목록과 페이지 읽기/클릭을 확인한다.
- CLI 환경에서 브라우저 도구가 없으면 사용 가능한 브라우저 MCP 또는 computer-use 연결을 확인한다. 도구 연결이 가능한 Codex 앱으로 현재 저장소를 여는 경로도 안내할 수 있다.

### Claude Code

- [공식 Chrome 연동 안내](https://code.claude.com/docs/en/chrome)를 읽고 현재 버전과 로그인 방식이 연동 조건에 맞는지 확인한다.
- 공식 Claude in Chrome 확장 프로그램 설치와 로그인을 확인하고 `/chrome`으로 연결 상태를 확인한다. 세션 시작 시 `claude --chrome`도 사용할 수 있다.
- 이미 연결된 브라우저 도구가 있으면 그대로 사용한다. 실패 시 확장 프로그램 활성화, 같은 브라우저 프로필, 사이트 권한과 연결 상태를 확인하고 공식 복구 절차를 적용한다.

### 사용자가 해야 할 단계가 생겼을 때

설치 페이지 또는 현재 인증 화면을 먼저 열고 다음 세 가지를 짧게 전달한다.

1. 지금 필요한 동작: 설치 버튼, 확장 프로그램 로그인, 연결 버튼 또는 사이트 권한 허용
2. 그 동작을 할 정확한 화면/주소와 버튼 이름
3. 완료 후 재개할 단계

예: “Chrome 연동 화면을 열었습니다. 공식 확장 프로그램을 설치하고 로그인한 뒤 이 사이트 접근을 허용해 주세요. 연결되면 제가 카카오 앱 설정부터 이어서 진행하겠습니다.”

로그인이나 CAPTCHA 단계에서도 같은 방식으로 현재 화면을 준비하고 사용자에게 필요한 행동만 요청한다. 인증 완료 후 새 화면을 읽고 해당 단계부터 이어 간다. 브라우저 연결을 기다리는 동안 Python 준비와 기존 연결 점검을 계속한다. 사이트 차단이 계속되면 오류와 정책을 확인하고 실제로 사용할 수 있는 도구/권한 복구 방법을 준비한다. 사용자에게 전체 설치 절차를 수동으로 넘기는 것은 사용자가 직접 진행하기를 선택했거나 현재 도구의 연결 조건을 해결할 수 없을 때다.

## 3. 로컬 설정 창과 카카오 앱

1. 같은 PC에서 실행 중인 설정 창이 있으면 재사용한다. 새 실행은 `setup.ps1 -NoBrowser` 또는 `py -3 -B -X utf8 <저장소>/scripts/kakao_me.py setup --no-browser`를 사용한다. 터미널에 출력된 `setup_url`을 현재 브라우저 도구로 연다. 이 프로세스는 설정을 마칠 때까지 유지한다.
2. 기존 프로필의 진행 상태를 확인한다. 새 앱이 필요하면 [카카오 앱 관리](https://developers.kakao.com/console/app)를 같은 브라우저의 별도 탭에 연다.
3. 현재 계정과 앱 목록을 확인한다. 개발자 가입 또는 본인 인증이 필요한 화면에서는 해당 조작만 사용자에게 요청한다. 기존 개인 알림 앱이 있으면 재사용하고, 새 앱은 화면이 요구하는 필수 정보를 입력해 만든다.
4. 선택한 앱에서 카카오 로그인 사용 설정을 ON으로 저장한다. `카카오 로그인 > 동의항목`에서 `카카오톡 메시지 전송(talk_message)`을 선택 동의 또는 이용 중 동의로 설정한다. 화면이 바뀌었으면 현재 UI와 공식 문서에서 설정 위치를 찾는다.
5. `앱 > 플랫폼 키 > REST API 키`에서 설정 창의 `앱에 등록할 콜백 주소`를 그대로 등록한다. `localhost`와 `127.0.0.1`을 섞지 않고 포트와 경로까지 일치시킨다.
6. 같은 앱의 REST API 키와 클라이언트 시크릿을 확인해 로컬 창의 해당 입력란에 넣고 `앱 설정 저장`을 누른다. 새 REST API 키는 시크릿이 기본 활성화된다. 민감한 값을 도구 결과나 채팅에 출력하지 않고 실행 중 변수 또는 지원되는 복사/붙여넣기로 전달한다. 도구가 비밀 입력을 사용자에게 맡기도록 요구하면 로컬 입력란을 준비하고 그 입력만 요청한다.

기존 키를 유지할 때 입력란은 비워 둔다. 다른 앱으로 교체하는 경우에만 `다른 앱으로 교체하고 로그인과 템플릿을 다시 연결`을 선택한다. 기존 암호화 프로필의 백업이 저장된다.

매 실행의 `redirect_uri`가 기준이다. 기존 주소가 있으면 재사용하고 사용 중인 포트는 자동으로 피한다. `callback_changed`가 참이면 앱에 새 주소를 추가한 뒤 로컬 `앱 설정 저장`을 누른다. 세션용 `setup_url`과 OAuth용 `redirect_uri`를 구분한다. 주소를 지정할 때는 [콜백 명령](setup.md)의 `--redirect-uri`를 사용한다. 다른 앱과 서비스가 사용하는 등록 주소는 보존한다.

### 비밀값 출력 방지

- 키 화면에 진입하기 전에 자동으로 원본 화면을 출력하는 도구 사용을 멈춘다. 원본 DOM/AX 스냅샷과 키가 보이는 스크린샷을 도구 출력, 채팅, 파일 또는 Git에 남기지 않는다.
- 필요한 키와 시크릿은 읽기 전용 DOM 조회 결과를 실행 중 변수에만 보관하고, 같은 PC의 로컬 설정 입력란으로 전달한다. 출력은 저장 성공 여부, 로그인 상태처럼 비밀값이 없는 명시적 상태만 허용한다. 처리 후 변수 참조를 비운다. 필요한 값만 조회하고 비즈니스 인증 등 이번 연결과 무관한 시크릿은 읽지 않는다.
- 16진수 전용 정규식을 임시로 만들어 쓰지 않는다. 시크릿은 영문 대소문자·숫자·기호가 섞이거나 여러 DOM 노드에 나뉠 수 있다.
- 출력이 꼭 필요한 진단 문자열은 `scripts/redact_snapshot.mjs`의 `redactSnapshot`을 먼저 통과시킨다. 이 함수는 키·시크릿·토큰 화면을 감지하면 문자열 전체를 숨기며, 그 밖의 문자열에서는 알고 있는 비밀값과 긴 토큰 후보를 가린다. 보조 정규식이 모든 비밀값을 탐지한다는 보장은 없으므로 원본 키 화면 출력 금지는 그대로 적용된다.

브라우저 JavaScript 도구에서 로컬 모듈 가져오기를 지원하면 실제 설치 경로의 모듈을 사용한다. 아래의 `snapshot`과 `knownSecrets`는 실행 중 변수이며 값 자체를 출력하지 않는다.

```javascript
const { redactSnapshot } = await import('file:///C:/path/to/minki-kakao-me/scripts/redact_snapshot.mjs');
const safeSnapshot = redactSnapshot(snapshot, { knownSecrets });
// 도구에서 문서화한 텍스트 출력 함수에 safeSnapshot만 전달한다.
```

가져오기를 지원하지 않는 도구에서는 임시 마스킹 함수를 재작성하지 말고 비밀값 없는 상태 요약만 출력한다. 전송용 Python 코드에는 Node 의존성을 추가하지 않는다. 도우미 회귀 테스트는 Node가 있는 개발/CI 환경에서 가짜 값만으로 실행한다.

```powershell
node --test tests/test_browser_redaction.mjs
```

## 4. OAuth 연결

1. 로컬 설정 창에서 `카카오 로그인`을 누른다. 본인 계정으로 로그인하고 메시지 전송 동의를 진행한다. 비밀번호와 추가 인증이 필요한 단계는 사용자에게 맡긴다.
2. 콜백 후 로컬 화면에서 `카카오 계정 연결됨`을 확인한다. `전송 동의 확인`을 실행해 서버의 `talk_message` 동의도 확인한다.
3. 오류 코드가 나타나면 `action`에 있는 복구 방법으로 앱 설정을 수정하고 로그인부터 재개한다. 이미 완료한 앱 생성과 다른 설정은 유지한다.

## 5. 텍스트 템플릿부터 등록

1. [메시지 템플릿 도구](https://developers.kakao.com/tool/template-builder/app)를 열고 OAuth에 사용한 앱을 선택한다.
2. 현재 앱에 같은 역할의 템플릿이 있으면 구성과 인자를 확인해 재사용한다. 새로 만들 때의 정확한 구성은 [templates.md](templates.md)의 텍스트용 피드 A형을 따른다.
3. 브라우저 도구로 제목 `${TITLE}`, 본문 `${TEXT}`, 버튼/이미지 OFF와 링크 없음 상태를 입력하고 저장한다. 나에게 보내기 전용 사용자 정의 템플릿의 사용 목적은 `카카오톡 공유`다.
4. 로컬 화면 3단계의 `기본 알림 연결`을 펼쳐 저장한 템플릿 ID를 `텍스트 템플릿 ID`에 넣고 `템플릿 설정 저장`을 누른다. 사진용 ID는 `사진 알림 연결`에 입력한다. ID 입력은 AI가 맡는다.
5. 사진 또는 링크가 요청되면 이미지 템플릿과 실제 목적지 도메인을 추가로 등록한다. 첫 텍스트 메시지만 필요한 경우 텍스트 템플릿 하나로 진행한다.

## 템플릿 선택과 버튼 링크

1. `templates` 명령 또는 로컬 화면의 `전송할 템플릿`에서 기본 6종과 저장한 목록을 확인한다. 사용자 요청에 맞는 이름을 선택한다.
2. 제목, 본문, 사진 URL과 버튼별 문구/링크를 입력한다. 모바일 목적지가 다르면 해당 버튼의 `모바일 전용 링크`를 펼친다. 필요한 도메인을 현재 앱 제품 링크 관리에 등록하고 로컬 `링크 도메인 등록`에도 반영한다.
3. `전송 구성 확인`으로 실제 입력을 검증한다. 자주 쓰는 구성은 `이 구성을 내 템플릿으로 저장`에서 의미 있는 이름을 붙인다. 기존 템플릿을 수정하면 같은 이름으로, 복제하려면 새 이름으로 저장한다.
4. 카카오의 별도 카드 디자인을 사용하려면 현재 앱의 템플릿을 만들거나 재사용하고 `개별 카카오 템플릿 ID`에 연결한다. 버튼과 이미지 개수 및 [표준 인자](templates.md#개별-카카오-템플릿과-링크-인자)를 정확히 맞춘다.
5. 전송 요청에 선택한 이름과 이번 내용을 반영한다. CLI는 `send --template '<이름>' --text '<본문>'` 또는 메시지 JSON의 `template`을 사용한다. 버튼이나 이미지 변경은 메시지 파일로 입력한다.

## 6. 첫 발송과 이어 쓰기

- 사용자가 첫 메시지 발송까지 요청했다면 로컬 화면에서 식별 가능한 짧은 본문을 확인하고 `나에게 보내기`를 누른다. 설정만 요청했다면 `첫 메시지를 보낼 준비가 되었습니다`까지 진행한다.
- `result_code: 0`을 확인한다. 사용 가능한 카카오톡 화면에서도 읽을 수 있으면 실제 메시지를 확인한다. 사용자가 확인해야 하는 경우 마지막에 “나와의 채팅에서 이 메시지를 확인해 주세요”라고 요청한다.
- `delivery_unknown`이면 앞선 발송을 확인하고 같은 request ID를 유지한다. 새 ID를 만들어 우회 재발송하지 않는다.
- `설정 종료`를 누른다. 이후에는 기존 `send` 명령과 `SKILL.md`로 메시지를 보낸다.

## 완료 기록
